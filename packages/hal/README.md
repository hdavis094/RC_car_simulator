# Desktop HAL

`bin/build-sim <project-dir>` builds a firmware project's `src/*.cpp` and `include/` with `$CXX` (default `c++`) and writes `.rcsim/build/firmware`. The driver invokes the compiler directly, forwards its diagnostics, and returns its exit status. HAL headers come first; the portable ArduinoJson 7 header is included as a system library. `make` caches the static library by compiler and invalidates it when compiler identity, flags, sources or headers change.

The sim listens on a Unix socket under `/tmp`, shorter than 100 bytes, and starts the executable with `RCSIM_SOCKET` set to that path. The firmware sends HELLO, receives CONFIG and its first STEP, then calls `setup()` once and `loop()` repeatedly. No firmware thread or wall clock is involved. An advance stops at each tick boundary, exchanges STEP_DONE for the next STEP, and carries the remaining nanoseconds on the ordinary C++ call stack. This permits `setup()`, delays and busy waits to span ticks. Uptime starts at the first STEP of each firmware process; wire timestamps remain run time. BYE exits successfully with its message; socket loss or malformed input prints a diagnostic and exits nonzero.

The protocol codec uses a JSON-shaped internal message matching the golden-vector documents. It checks frame, string, array and serial limits, strict UTF-8, enums, booleans, optional tags, safe u64s, finite f32s and complete payload consumption. Network reads handle partial stream frames. All valid vectors are compared with their JSON and re-encoded in both directions; all malformed vectors must throw.

`Wire.begin(sda, scl)` must match a configured bus. The library shims route through that bus and its current device addresses. An enabled VL53L0X boots at its configured default address, XSHUT low resets it, and colliding addresses fail to answer. Firmware must bring the parts up one at a time. Raw Wire transactions support address probing; arbitrary register emulation is outside the shim model. MPU6050 supports the register API listed in the schema README, with SI readings converted into the selected raw full-scale counts. DMP is unsupported. ADC uses a clamped, linear 12-bit 0–3.3 V model; it does not model hardware calibration or nonlinearity.

Wi-Fi connects immediately. TCP listeners and UDP binds use nonblocking IPv4 POSIX sockets, bind to CONFIG's address on an ephemeral host port and report LISTEN mappings. TCP client copies share ownership of the connection. Accepted connections, explicit stops, peer disconnects, listener stops and release of the last socket handle produce net events. Incoming and outgoing traffic passes through bounded queues; fault latency uses sim time and loss uses a CONFIG-seeded generator. Dropout discards new traffic and pauses queued traffic until cleared. TCP fault loss discards buffered segments at the HAL boundary, without modelling TCP retransmission. Numeric IPv4 addresses and `localhost` are supported; DNS, IPv6 and Wi-Fi radio/authentication behaviour are not modelled. Firmware sockets advance only at HAL boundaries; live host traffic remains nondeterministic.

Run `pnpm --filter @rcsim/hal test` for doctest with every available distinct GCC/Clang compiler. The suite covers the API areas, every protocol vector, precise delays and GPIO pulses, sensor address sequencing, real TCP/UDP traffic and fault injection, compiler diagnostics, socket loss, and a built firmware process driven for 400 ticks by a C++ fake sim. The integration firmware lives in `test/fixtures/firmware/`; the starter firmware is owned by P1-G. Only macOS CI can establish Apple clang and macOS runtime behaviour.

Host integration tests use bounded `poll` barriers on the borrowed native `fd()` of clients, listeners and UDP sockets before making receive or injected-latency assertions. These descriptor accessors do not advance sim time or pump traffic; server/UDP descriptors are sim extensions. The tests keep OS delivery time separate from injected sim-time latency, and confirm that a later receive succeeds after an earlier empty nonblocking poll.
