# Desktop HAL

`bin/build-sim <project-dir>` builds a firmware project's `src/*.cpp` and `include/` with `$CXX` (default `c++`) and writes `.rcsim/build/firmware`. The driver invokes the compiler directly, forwards its diagnostics, and returns its exit status. HAL headers come first; the portable ArduinoJson 7 header is included as a system library. The driver publishes an immutable static-library cache keyed by compiler command/version, flags and HAL source contents. First builders use private temporary directories and publish with an atomic rename; concurrent builders can safely share the completed entry. Library builds allow warnings; HAL tests retain `-Werror`. `$CXX` supports launchers such as `ccache g++` and quoted executable paths without shell evaluation.

The sim listens on a Unix socket under `/tmp`, shorter than 100 bytes, and starts the executable with `RCSIM_SOCKET` set to that path. The firmware sends HELLO, receives CONFIG and its first STEP, then calls `setup()` once and `loop()` repeatedly. Firmware time advances only through HAL; no firmware thread is involved. Outbound TCP connection establishment uses a bounded host-time poll without advancing the sim clock, so `connect()` returns failure synchronously. An advance stops at each tick boundary, exchanges STEP_DONE for the next STEP, and carries the remaining nanoseconds on the ordinary C++ call stack. This permits `setup()`, delays and busy waits to span ticks. Uptime starts at the first STEP of each firmware process; wire timestamps remain run time. `exit()` from firmware reports BYE(firmware-exit) through an `atexit` handler. A sim BYE exits successfully with its message; socket loss or malformed input prints a diagnostic and exits nonzero.

The protocol codec uses a JSON-shaped internal message matching the golden-vector documents. It checks frame, string, array and serial limits, strict UTF-8, enums, booleans, optional tags, safe u64s, finite f32s and complete payload consumption. Network reads handle partial stream frames. All valid vectors are compared with their JSON and re-encoded in both directions; all malformed vectors must throw.

`Wire.begin(sda, scl)` must match a configured bus. The library shims route through that bus and its current device addresses. An enabled VL53L0X boots at its configured default address, XSHUT low resets it, and colliding addresses fail to answer. Firmware must bring the parts up one at a time. Switching XSHUT from OUTPUT/LOW to INPUT or INPUT_PULLUP releases the line to the carrier pull-up, matching the standard Pololu sequence. Raw Wire transactions support address probing; arbitrary register emulation is outside the shim model. MPU6050 supports the register API listed in the schema README, with SI readings converted into the selected raw full-scale counts. DMP is unsupported. ADC defaults to a clamped, linear 12-bit 0–3.3 V model, with `analogReadResolution` supporting 1–16 bits; it does not model hardware calibration or nonlinearity.

Wi-Fi connects immediately. TCP listeners and UDP binds use nonblocking IPv4 POSIX sockets, bind to CONFIG's address on an ephemeral host port and report LISTEN mappings. TCP client copies share ownership of the connection. Accepted connections, explicit stops, peer disconnects, listener stops and release of the last socket handle produce net events. Incoming and outgoing traffic passes through bounded queues; fault latency uses sim time and loss uses a CONFIG-seeded generator. Dropout discards new traffic and pauses queued traffic until cleared. TCP fault loss discards buffered segments at the HAL boundary, without modelling TCP retransmission. Numeric IPv4 addresses and `localhost` are supported; DNS, IPv6 and Wi-Fi radio/authentication behaviour are not modelled. Firmware sockets advance only at HAL boundaries; live host traffic remains nondeterministic.

Run `pnpm --filter @rcsim/hal test` for doctest with every available distinct GCC/Clang compiler. The suite covers the API areas, every protocol vector, precise delays and GPIO pulses, sensor address sequencing, real TCP/UDP traffic and fault injection, compiler diagnostics, socket loss, and a built firmware process driven for 400 ticks by a C++ fake sim. The integration firmware lives in `test/fixtures/firmware/`; the starter firmware is owned by P1-G. Only macOS CI can establish Apple clang and macOS runtime behaviour.

Host integration tests use bounded `poll` barriers on client `fd()` and `rcsim::hal::socketFd(server/udp)` before making receive or injected-latency assertions. These descriptor accessors do not advance sim time or pump traffic; `rcsim::hal::hostPort(server)` and the server/UDP descriptors are host-only free functions declared in `rcsim/network.h`, so the firmware-facing classes keep Arduino-compatible interfaces. The tests keep OS delivery time separate from injected sim-time latency, and confirm that a later receive succeeds after an earlier empty nonblocking poll.

Core compatibility also includes Printable/IPAddress output, length-delimited character writes, Stream parsing and reads, Arduino numeric String concatenation/edits, seeded `random`/`randomSeed`, analog PWM, math helpers and common-type `constrain`. Firmware randomness starts from CONFIG's seed and can be explicitly reseeded; it never uses a wall clock. Serial accumulation and protocol arrays are traversed linearly, with coverage for a full 16 KiB serial frame and overflow to the following tick.

Packaging follow-up (P2-01): `#!/usr/bin/env node` requires Node on PATH, which a Finder-launched macOS app lacks. The cache currently lives inside this package and must move to a writable app cache when the package is bundled read-only. The driver does not change its own working directory: it runs Make in the HAL package and runs the firmware compiler in the car project directory, passing absolute firmware source paths. Relative firmware diagnostics therefore resolve against the project directory; internal HAL diagnostics from Make resolve against the HAL package.
